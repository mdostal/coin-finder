What actually touches the network

Every network call this app can make, in full -- not a vague "be careful," the real list, sourced from the code itself. Nothing here is hidden or approximate.

Right now this machine looks: {{ network_status }}

1. The connectivity check itself

Opens a bare TCP connection (no data sent -- just the handshake, then closes it) to three public DNS resolvers: 8.8.8.8, 1.1.1.1, 9.9.9.9 on port 53. That's it -- this is purely "is there a network at all," not a request that carries any information about you, your wallet, or your coins. (tools/unlock_wallet.py, check_network_status)

2. Balance checks -- sends a public address, nothing else

When you check a balance, the address (e.g. 1abc...) -- public by definition, meant to be looked up on-chain by anyone -- goes to a public blockchain explorer API (Blockstream for BTC, Blockchair, Etherscan, etc., one per coin -- see the full list in the README). There's no way to check a live balance without asking a blockchain explorer -- this is unavoidable and it's the same public information a block explorer website shows anyone who types the address in. Nothing else about the wallet file goes with it: no private keys, no passwords, no seed phrases, no filenames.

3. Unlock & Extract Key -- never sends anything, period

Candidate passwords, extracted private keys, and seed phrases never travel over the network in any code path in this project -- they only ever touch local temp files. The offline-by-default gate on these two pages exists for a different, local reason: if the machine itself were ever compromised (malware, a keylogger, anything), being online during the brief window an unlock attempt runs means a candidate password list and the real wallet file are sitting together on a machine that can talk to the outside world. Offline removes that risk category entirely for those couple of minutes -- the same reasoning BTCRecover itself and hardware-wallet vendors give for the same recommendation. It's a precaution against the machine being compromised, not a claim that this app itself would ever send a key anywhere -- and it's fully your call: one checkbox overrides it, every time, no exceptions.

4. Google Drive scan -- only your own files, via your own OAuth token

Only runs if you set it up. Talks to Google's own Drive API using a token you authorize yourself, only lists/downloads files already in your own Drive. Nothing wallet-related is sent to Google -- it's the same as browsing your own Drive in a file manager.

5. Update check -- a version number, nothing else

The Update page checks GitHub's public releases API for the latest version tag. No wallet data involved.

6. Password vault -- local only

The vault resolves saved passwords via a local subprocess to local files (Portunus, or its local fallback store) -- no network call at all.

7. AI assist -- only if you set it up, only your typed question

The cloud setup wizard's optional "Ask AI" panel is bring-your-own-key: nothing is sent anywhere until you paste your own Anthropic API key and click Ask. Each question sends only your typed text plus a short fixed description of what the wizard is for -- never a wallet file, address, password, or key. The key itself lives in the vault (Portunus), the same place every other secret in this app does. (web/ai_assist.py)

That's the complete list. If you find a network call this page doesn't mention, that's a bug worth reporting.
